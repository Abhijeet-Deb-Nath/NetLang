## Overview

The **Lexical Analysis Phase** (also called **Lexing** or **Scanning**) is the **first stage** of the NetLang compiler. Its primary responsibility is to read the raw source code character by character and convert it into a stream of **tokens** that the parser can understand.

**File Location**: `src/lexer/net_lang.l`

**Tool Used**: **Flex** (Fast Lexical Analyzer Generator)

**Generated Output**: `build/lex.yy.c` (C source code with lexer implementation)

---

## What is Facilitating Lexical Analysis

### 1. **Flex (Lexical Analyzer Generator)**

Flex is a tool that generates C code for lexical analysis. You write pattern-matching rules in a `.l` file, and Flex generates a C function called `yylex()` that implements those rules.

**Why Flex?**
- **Pattern Matching**: Uses regular expressions to recognize tokens
- **Automatic Code Generation**: Converts high-level rules into efficient C code
- **Integration**: Designed to work seamlessly with Bison (parser generator)
- **Performance**: Generates fast, optimized scanners

### 2. **Regular Expressions**

The lexer uses regular expressions to define patterns:
```c
DIGIT       [0-9]              // Any single digit
INTEGER     {DIGIT}+           // One or more digits
FLOAT       {DIGIT}+"."{DIGIT}* // Number with decimal point
ID          [a-zA-Z_][a-zA-Z0-9_]*  // Identifier (variable name)
```

These patterns are used to match sequences of characters in the source code.

## File Structure and Components

### Section 1: Definitions (Between `%{` and `%}`)

```c
%{
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include "../ast/ast.h"
#include "net_lang.tab.h"  /* Generated by Bison - contains token codes */

int yycolumn = 1;

#define YY_USER_ACTION \
    yylloc.first_line = yylloc.last_line = yylineno; \
    yylloc.first_column = yycolumn; \
    yylloc.last_column = yycolumn + yyleng - 1; \
    yycolumn += yyleng;
%}
```

**Purpose of Each Include:**

1. **`net_lang.tab.h`**: 
   - Generated by Bison
   - Contains `#define` statements for all token types (NETWORK = 258, MODULE = 259, etc.)
   - Defines the `YYSTYPE` union (for passing values)
   - Defines `yylval` (the variable that holds token values)
   - Defines `YYLTYPE` structure (for location tracking)

2. **`ast.h`**: 
   - Contains AST node definitions
   - Provides `ActivationType` enum used in the union

**Global Variables:**

- **`yycolumn`**: Tracks current column position (for error reporting)
- **`yylineno`**: Automatically maintained by Flex (tracks line number)
- **`yyleng`**: Length of current token (set by Flex)
- **`yytext`**: Pointer to matched text (set by Flex)

**`YY_USER_ACTION` Macro:**

This macro is executed **before every token action**. It updates location information:
- `yylloc.first_line`: Starting line of token
- `yylloc.last_line`: Ending line of token
- `yylloc.first_column`: Starting column
- `yylloc.last_column`: Ending column
- Updates `yycolumn` for next token

### Section 2: Options

```c
%option noyywrap
%option yylineno
```

**`%option noyywrap`**: 
- Tells Flex we're only processing one file
- Without this, Flex would call `yywrap()` at EOF to check for more files

**`%option yylineno`**: 
- Enables automatic line number tracking
- Flex maintains `yylineno` variable automatically

### Section 3: Start Conditions

```c
%x COMMENT
```

**Start Condition** is a state machine mechanism in Flex:
- **`%x COMMENT`**: Defines an **exclusive** start condition for multi-line comments
- When in COMMENT state, only rules marked `<COMMENT>` will match
- Used to handle `/* ... */` comments that span multiple lines

### Section 4: Pattern Definitions

```c
DIGIT       [0-9]
INTEGER     {DIGIT}+
FLOAT       {DIGIT}+"."{DIGIT}*
ID          [a-zA-Z_][a-zA-Z0-9_]*
STRING      \"[^\"]*\"
WS          [ \t\r]
NEWLINE     \n
SLCOMMENT   "//"[^\n]*
```

These are **named patterns** that can be referenced in rules using `{NAME}` syntax.

## How Tokenization Works

### The Matching Process

When `yylex()` is called:

1. **Read Characters**: Flex reads characters from input stream
2. **Find Longest Match**: Tries to match the longest possible pattern
3. **Execute Action**: Runs the corresponding C code for matched pattern
4. **Return Token**: Returns token code to parser
5. **Repeat**: Parser calls `yylex()` again for next token

### Example: Processing `"network MNIST_CNN {"`

Let's trace how this input is tokenized:

```
Input: "network MNIST_CNN {"
       ^
```

**Step 1**: Try to match starting from 'n'
- Tries keyword patterns first
- Matches `"network"` (7 characters)
- Executes: `return NETWORK;`
- Returns token code **258** (NETWORK)
- Parser receives it

**Step 2**: Whitespace
```
Input: "network MNIST_CNN {"
               ^
```
- Matches `{WS}+` (space)
- Executes: `/* Ignore whitespace */`
- **Does NOT return** to parser
- Continues scanning

**Step 3**: Identifier
```
Input: "network MNIST_CNN {"
                ^
```
- Matches `{ID}` pattern: `[a-zA-Z_][a-zA-Z0-9_]*`
- Matches "MNIST_CNN"
- Executes:
  ```c
  yylval.sval = strdup(yytext);  // Copy "MNIST_CNN" to yylval
  return IDENTIFIER;
  ```
- Returns token code **287** (IDENTIFIER)
- Parser can access the string via `yylval.sval`

**Step 4**: Left Brace
```
Input: "network MNIST_CNN {"
                          ^
```
- Matches `"{"`
- Executes: `return LBRACE;`
- Returns token code **289**

## Token-to-Parser Communication

### The Communication Channel: `yylval`

**`yylval`** is a **union** defined in `net_lang.tab.h`:

```c
union YYSTYPE {
    int ival;              // For integers
    float fval;            // For floating-point numbers
    char* sval;            // For strings and identifiers
    ASTNode* node;         // For AST nodes (used by parser)
    ASTList* list;         // For lists of nodes
    ParameterList* params; // For parameter lists
    ActivationType activation;  // For activation functions
    NetworkBody* netbody;  // For network body collection
};

extern YYSTYPE yylval;  // Global variable shared between lexer and parser
```

**How It Works:**

1. **Lexer Sets It**: Before returning a token, lexer stores value in appropriate union field
2. **Parser Reads It**: Parser accesses the value through `yylval`
3. **Type Safety**: Union ensures only one value at a time

### Token Return Mechanism

```c
int yylex(void)
```

The `yylex()` function returns an **integer** representing the token type:
- Keywords: NETWORK (258), MODULE (259), etc.
- Literals: NUMBER (285), IDENTIFIER (287), etc.
- Punctuation: LBRACE (289), COMMA (296), etc.

**Return value 0** means **EOF** (End of File)

### Complete Communication Flow

```
┌─────────────────┐
│  Source Code    │ "Conv2D"
└────────┬────────┘
         │
         ▼
┌─────────────────┐
│  yylex()        │ 1. Reads "Conv2D"
│  (Lexer)        │ 2. Matches pattern "Conv2D"
└────────┬────────┘ 3. Executes: return CONV2D;
         │
         │ Returns: 265 (token code)
         │
         ▼
┌─────────────────┐
│  yyparse()      │ Receives token 265
│  (Parser)       │ Knows it's CONV2D
└─────────────────┘ Applies grammar rule
```

## Value Passing Mechanism

Different token types pass values differently. Let's examine each category:

### 1. **Keywords (No Value Needed)**

```c
"network"     { return NETWORK; }
"module"      { return MODULE; }
"return"      { return RETURN; }
```

**Mechanism:**
- Only the token **type** matters
- No semantic value is stored in `yylval`
- Parser just needs to know "this is a network keyword"

### 2. **Integer Numbers**

```c
{INTEGER}     { 
    yylval.ival = atoi(yytext);  // Convert string to integer
    return NUMBER; 
}
```

**Detailed Process:**

1. **Pattern Matches**: `{INTEGER}` matches "32"
2. **`yytext` Contains**: "32" (as a string)
3. **Conversion**: `atoi("32")` converts to integer `32`
4. **Storage**: Stored in `yylval.ival`
5. **Return**: Returns token code `NUMBER` (285)
6. **Parser Access**: Parser reads `$1` which maps to `yylval.ival`, gets `32`

**Example Flow:**
```
Source: "filters: 32"
         Matches INTEGER
         yytext = "32"
         yylval.ival = atoi("32") = 32
         return NUMBER
         
Parser sees: token=NUMBER, value=32
```

### 3. **Floating-Point Numbers**

```c
{FLOAT}       { 
    yylval.fval = atof(yytext);  // Convert string to float
    return FLOAT_NUM; 
}
```

**Example:**
```
Source: "0.001"
        yytext = "0.001"
        yylval.fval = atof("0.001") = 0.001
        return FLOAT_NUM
```

### 4. **Identifiers (Variable Names)**

```c
{ID}          { 
    yylval.sval = strdup(yytext);  // Allocate and copy string
    return IDENTIFIER; 
}
```

**Detailed Memory Management:**

1. **Pattern Matches**: Identifier like "x", "conv1", "MNIST_CNN"
2. **`yytext` Points To**: Internal Flex buffer (will be overwritten!)
3. **`strdup(yytext)`**: 
   - Allocates new memory on heap
   - Copies the string
   - Returns pointer to new memory
4. **Storage**: Pointer stored in `yylval.sval`
5. **Parser Receives**: Pointer to a persistent copy

**Why `strdup`?**
- Flex reuses the `yytext` buffer for each token
- Without copying, the string would be lost when next token is scanned
- `strdup` creates a **permanent** copy on the heap

**Memory Lifecycle:**
```
Lexer:   strdup("my_var") → allocates memory → yylval.sval = 0x12345
Parser:  Receives pointer 0x12345 → creates AST node → stores pointer
AST:     AST node contains pointer 0x12345
Later:   When AST is destroyed, memory must be freed
```

### 5. **String Literals**

```c
{STRING}      { 
    /* Remove quotes from string */
    int len = strlen(yytext) - 2;  // Exclude quotes
    yylval.sval = (char*)malloc(len + 1);  // Allocate
    strncpy(yylval.sval, yytext + 1, len); // Copy without first quote
    yylval.sval[len] = '\0';  // Null terminate
    return STRING_LIT; 
}
```

**Example:**
```
Source: "weights.bin"
        yytext = "\"weights.bin\""  (with quotes)
        len = 13 - 2 = 11
        Allocate 12 bytes (11 + null terminator)
        Copy from yytext+1 (skip first ") → "weights.bin"
        Add '\0' at end
        yylval.sval → "weights.bin" (no quotes)
        return STRING_LIT
```

**Why Strip Quotes?**
- Parser and later phases need the actual string content
- Quotes are syntax, not data

### 6. **Activation Functions (Special Case)**

```c
"relu"        { yylval.sval = strdup(yytext); return RELU; }
"sigmoid"     { yylval.sval = strdup(yytext); return SIGMOID; }
"tanh"        { yylval.sval = strdup(yytext); return TANH; }
"softmax"     { yylval.sval = strdup(yytext); return SOFTMAX; }
"linear"      { yylval.sval = strdup(yytext); return LINEAR; }
```

**Why Both Token Code AND String Value?**

1. **Token Code**: Lets parser know it's an activation function
2. **String Value**: Parser can convert to `ActivationType` enum or store for later

**Parser Usage:**
```c
activation_value:
    RELU     { $$ = ACT_RELU; }
  | SIGMOID  { $$ = ACT_SIGMOID; }
  | TANH     { $$ = ACT_TANH; }
  ...
```

## Location Tracking System

### The `YYLTYPE` Structure

```c
typedef struct YYLTYPE {
    int first_line;    // Line where token starts
    int first_column;  // Column where token starts
    int last_line;     // Line where token ends
    int last_column;   // Column where token ends
} YYLTYPE;

extern YYLTYPE yylloc;  // Global location variable
```

### Automatic Location Updates

Every token action updates location via `YY_USER_ACTION`:

```c
#define YY_USER_ACTION \
    yylloc.first_line = yylloc.last_line = yylineno; \
    yylloc.first_column = yycolumn; \
    yylloc.last_column = yycolumn + yyleng - 1; \
    yycolumn += yyleng;
```

**Example:**
```
Source code line 5: "    Conv2D(filters: 32)"
                     ^--- column 5
                     
Token: "Conv2D" (6 characters)
Before: yylloc = {?, ?, ?, ?}, yycolumn = 5
Action: 
  yylloc.first_line = 5
  yylloc.last_line = 5
  yylloc.first_column = 5
  yylloc.last_column = 5 + 6 - 1 = 10
  yycolumn = 5 + 6 = 11
After: yylloc = {5, 5, 5, 10}, yycolumn = 11
```

### Newline Handling

```c
{NEWLINE}     { yycolumn = 1; }
```

When newline is encountered:
- `yylineno` is automatically incremented by Flex
- `yycolumn` is reset to 1

### Usage in Error Messages

Parser can use location information:

```c
void yyerror(const char* s) {
    fprintf(stderr, "Line %d:%d-%d: %s\n",
            yylloc.first_line,
            yylloc.first_column,
            yylloc.last_column,
            s);
}
```

**Output:**
```
Line 5:5-10: syntax error, unexpected CONV2D
```

## Comment Handling

### Single-Line Comments

```c
SLCOMMENT   "//"[^\n]*

{SLCOMMENT}   { /* Ignore single-line comments */ }
```

**How It Works:**
- Pattern: `"//"` followed by any characters except newline
- Matches: `// This is a comment`
- Action: Empty (just ignore, don't return token)
- Newline is NOT consumed (handled separately)

**Example:**
```
Source: "network CNN { // Define network"
                      ^
                      Matches "// Define network"
                      Action: (nothing - ignore)
                      Continues to newline
```

### Multi-Line Comments

```c
%x COMMENT   // Define start condition

"/*"          { BEGIN(COMMENT); }
<COMMENT>"*/" { BEGIN(INITIAL); }
<COMMENT>\n   { yycolumn = 1; }
<COMMENT>.    { /* Ignore comment content */ }
```

**State Machine:**

1. **INITIAL State** (normal scanning)
   - Encounters `"/*"` → Switch to COMMENT state

2. **COMMENT State** (inside comment)
   - `"*/"` → Switch back to INITIAL state
   - `\n` → Reset column counter
   - `.` (any other character) → Ignore

**Example:**
```
Source:
network CNN {
    /* This is a
       multi-line
       comment */
    input(shape: [28, 28, 1])
}

Step 1: Match "network" → return NETWORK
Step 2: Match "CNN" → return IDENTIFIER
Step 3: Match "{" → return LBRACE
Step 4: Match "/*" → BEGIN(COMMENT), no return
        Inside COMMENT state:
        Match " This is a\n" → ignore
        Match "       multi-line\n" → ignore
        Match "       comment " → ignore
        Match "*/" → BEGIN(INITIAL), no return
Step 5: Match "input" → return INPUT
...
```

## Error Handling

### Unrecognized Characters

```c
.             {
    fprintf(stderr, "Line %d: Lexical error - unexpected character '%s'\n", 
            yylineno, yytext);
    return yytext[0];
}
```

**Catch-All Rule:**
- `.` matches any single character not matched by other rules
- Prints error message to stderr
- Returns the character code itself (for parser to handle)

**Example:**
```
Source: "network CNN { @ }"
                      ^
                      Not matched by any rule
                      Executes catch-all
                      Output: Line 1: Lexical error - unexpected character '@'
                      Returns: 64 (ASCII code for '@')
                      Parser receives it, likely throws syntax error
```

### Why Return the Character?

Even though it's an error, returning something allows:
- Parser to potentially recover
- Better error messages (parser knows what caused the problem)
- Compilation to continue (find multiple errors)

## Integration with Next Phase (Parser)

### The Complete Handshake

```
┌──────────────────────────────────────────────────────┐
│                    LEXER (net_lang.l)                │
│                                                       │
│  1. Reads source code character by character         │
│  2. Matches patterns using regular expressions       │
│  3. Stores value in yylval union                     │
│  4. Updates location in yylloc                       │
│  5. Returns token code (integer)                     │
└───────────────┬──────────────────────────────────────┘
                │
                │ int yylex(void)
                │ Returns: token code
                │ Sets: yylval, yylloc
                │
                ▼
┌──────────────────────────────────────────────────────┐
│                  PARSER (net_lang.y)                 │
│                                                       │
│  1. Calls yylex() to get next token                  │
│  2. Receives token code                              │
│  3. Reads value from yylval                          │
│  4. Reads location from yylloc                       │
│  5. Applies grammar rules                            │
│  6. Builds AST nodes                                 │
└──────────────────────────────────────────────────────┘
```

### Data Structures Shared Between Lexer and Parser

#### 1. **Token Codes** (from `net_lang.tab.h`)

```c
#define NETWORK 258
#define MODULE 259
#define RETURN 260
...
```

Generated by Bison, included by Lexer. This ensures both agree on token numbers.

#### 2. **`yylval` (Value Container)**

```c
extern YYSTYPE yylval;
```

- Declared in `net_lang.tab.h`
- Written by lexer: `yylval.ival = 32;`
- Read by parser: `int filters = $1;` (where `$1` expands to `yylval.ival`)

#### 3. **`yylloc` (Location Container)**

```c
extern YYLTYPE yylloc;
```

- Declared in `net_lang.tab.h`
- Updated by lexer: `YY_USER_ACTION` macro
- Read by parser: `@1`, `@2` in actions (location of first, second symbol)

### Example: Complete Token Flow

**Source Code:**
```
Conv2D(filters: 32)
```

**Lexer Processing:**

| Call | Match | yytext | Action | Return | yylval | yylloc |
|------|-------|--------|--------|--------|--------|--------|
| 1 | `Conv2D` | "Conv2D" | `return CONV2D;` | 265 | - | {1,1,1,6} |
| 2 | `(` | "(" | `return LPAREN;` | 293 | - | {1,7,1,7} |
| 3 | `filters` | "filters" | `return FILTERS;` | 273 | - | {1,8,1,14} |
| 4 | `:` | ":" | `return COLON;` | 295 | - | {1,15,1,15} |
| 5 | (skip space) | " " | (no return) | - | - | - |
| 6 | `32` | "32" | `yylval.ival=32; return NUMBER;` | 285 | ival=32 | {1,17,1,18} |
| 7 | `)` | ")" | `return RPAREN;` | 294 | - | {1,19,1,19} |

**Parser Processing:**

```yacc
conv2d_layer:
    CONV2D LPAREN layer_param_list RPAREN {
        // $1 = CONV2D token (no value)
        // $2 = LPAREN token (no value)
        // $3 = layer_param_list (AST node for parameters)
        // $4 = RPAREN token (no value)
        $$ = ast_conv2d(@1.first_line, $3);
    }
;

layer_param_list:
    FILTERS COLON NUMBER {
        // $1 = FILTERS token
        // $2 = COLON token
        // $3 = NUMBER token, value in yylval.ival = 32
        Parameter* p = create_parameter("filters", 
                                        ast_number(@3.first_line, yylval.ival));
        // Create parameter with value 32
    }
;
```

### What Parser Receives

For each `yylex()` call, parser gets:

1. **Token Type** (return value): Identifies what kind of token
2. **Token Value** (via `yylval`): The actual data (if applicable)
3. **Token Location** (via `yylloc`): Where in source code
4. **Token Text** (via `yytext`): Original matched string (rarely used by parser)

### How Parser Uses This Information

```c
// Parser grammar rule
assignment:
    IDENTIFIER ASSIGN layer_expr FROM expr {
        // $1 corresponds to IDENTIFIER token
        //    yylval.sval contains the identifier string
        // $2 is ASSIGN (no value needed)
        // $3 is the layer expression (AST node)
        // $4 is FROM keyword
        // $5 is the source expression (AST node)
        
        $$ = ast_assignment(@1.first_line,  // Line number from location
                           $1,              // Identifier string from yylval.sval
                           $3,              // Layer AST node
                           $5);             // Source AST node
    }
;
```

### The `$$` and `$n` Notation

- **`$1`, `$2`, `$3`...**: Value of 1st, 2nd, 3rd symbol in the rule
- **`$$`**: Value to be assigned to the left-hand side (the result)
- **`@1`, `@2`, `@3`...**: Location of 1st, 2nd, 3rd symbol
- **`@@`**: Location of the entire rule (computed from `@1` to `@n`)

**Type Safety:**

The `%type` declarations in parser specify which union field to use:

```yacc
%token <ival> NUMBER          // NUMBER uses yylval.ival
%token <sval> IDENTIFIER      // IDENTIFIER uses yylval.sval
%type <node> layer_expr       // layer_expr produces ASTNode*
```

When parser sees:
```yacc
layer_expr:
    CONV2D LPAREN params RPAREN {
        $$ = ast_conv2d(...);  // $$ is ASTNode* (node field)
    }
;
```

Bison knows `$$` should use the `node` field of the union.

## Summary: Complete Lexical Analysis Flow

### Input: Source Code
```
network MNIST_CNN {
    input(shape: [28, 28, 1])
}
```

### Processing Steps:

1. **Initialization**
   - Flex generated code sets up input buffer
   - `yylineno = 1`, `yycolumn = 1`

2. **First yylex() Call**
   - Reads 'n', 'e', 't', 'w', 'o', 'r', 'k'
   - Matches `"network"` pattern
   - Updates: `yylloc = {1, 1, 1, 7}`
   - Returns: `258` (NETWORK)

3. **Parser Receives**
   - Token type: NETWORK
   - No value needed
   - Location: line 1, columns 1-7

4. **Second yylex() Call**
   - Reads ' ' (space)
   - Matches `{WS}+`
   - Action ignores it
   - Continues without returning

5. **Third yylex() Call**
   - Reads 'M', 'I', 'S', 'T', '_', 'C', 'N', 'N'
   - Matches `{ID}` pattern
   - Executes: `yylval.sval = strdup("MNIST_CNN");`
   - Updates: `yylloc = {1, 9, 1, 16}`, `yycolumn = 17`
   - Returns: `287` (IDENTIFIER)

6. **Parser Receives**
   - Token type: IDENTIFIER
   - Value: `yylval.sval` → "MNIST_CNN"
   - Location: line 1, columns 9-16
   - Stores in AST node

7. **Process Continues...**
   - LBRACE, NEWLINE (ignored), INPUT, LPAREN, SHAPE, COLON, etc.

8. **End of File**
   - `yylex()` returns `0`
   - Parser knows input is complete
   - Finalizes AST construction

## Key Takeaways

1. **Lexer's Job**: Convert raw text → meaningful tokens
2. **Flex Tool**: Generates efficient C code from patterns
3. **Token Communication**: Via return value (type) + yylval (value) + yylloc (location)
4. **Value Passing**: Union allows different data types (int, float, string, pointers)
5. **Memory Management**: `strdup()` creates persistent copies of strings
6. **Location Tracking**: Enables precise error messages
7. **Whitespace/Comments**: Filtered out, never reach parser
8. **Integration**: Tight coupling with parser through shared data structures

The lexer is the **gatekeeper** of the compiler - it validates that every character forms a legal token and packages those tokens with their values and locations for the parser to construct meaningful program structure.
